# Why Loomit Exists

この文書は、Loomit の仕様や設計史ではなく、「なぜこのプロジェクトを始めたのか」を残すためのメモである。

`vision.md` が扱うのは、Loomit がどこを目指すかという将来の話である。`design-history.md` が扱うのは、設計が途中でどう変わったかという意思決定の話である。
この `why.md` では、その手前にある出発点、つまり「どんな困りごとから Loomit を作り始めたのか」を書く。

## 服作りでは、問題が見つかるのが遅い

服作りでは、型紙を見ているだけでは分からないことが多い。

- 袖ぐりと袖が本当に合うか
- 襟やカフスの組み合わせが成立するか
- 出来上がり寸法が着用に足りるか
- 動いたときにどこが突っ張るか

こうした問題は、実際に組み合わせたり、仮縫いしたり、布を切ったあとでようやく見えてくることが多い。

その結果として起きるのは、

- 何度も試作し直すこと
- 少しの変更のためにまた布を切ること
- 直したはずなのに、前回から何を変えたのか分からなくなること

である。

Loomit は、まずこの「問題が見つかるのが遅い」というつらさから始まっている。

## 作りたかったのは、完成品を並べるアプリではない

欲しかったのは、完成した服だけを管理するアプリではなかった。

むしろ必要だったのは、

- 今回の一着で何を試しているのか
- 前回案から何を変えたのか
- どのパーツは再利用したいのか
- どの失敗は次回に持ち越したい知見なのか

を残せる作業環境だった。

服作りでは、完成品そのものより、途中の判断の方が重要なことがある。
袖を少し直した、ダーツを動かした、前回は腕が上がりにくかった、残布は襟なら取れそうだった、といった情報は、次の一着を作るときに効いてくる。

Loomit は、その途中の判断と変更履歴を扱いたいという発想から生まれている。

## 洋裁に、ソフトウェア的な道具立てを持ち込みたかった

ソフトウェア開発では、

- Git で変更履歴を残す
- lint や test で壊れ方を早く見つける
- diff を読んで変更内容を確認する
- 再利用できる部品を資産として育てる

という流れが自然にある。

服作りにも、これに近い補助線があってよいのではないか、という考えが Loomit の根底にある。

もちろん、服はソフトウェアではない。布の伸び、体型、着心地、見た目のよさ、縫製方法など、人の手と身体に近い制約が多い。そのため、単純に Git をなぞれば解決するとは思っていない。

それでも、

- 変更をファイルとして残す
- 組み合わせの成立を事前に確認する
- 差分を意味のある単位で読む
- 試作メモを次の判断につなげる

といった考え方は、服作りにもかなり相性がよいはずだと感じている。

Loomit は、洋裁そのものをソフトウェア化したいのではなく、洋裁の試行錯誤を少し整理しやすくしたい。

## 一人で使う道具として始めたい

Loomit は、わたしが欲しかったツール。

- 今回の一着の状態をちゃんと残せる
- 自分の体型や好みに照らして確認できる
- 気に入ったパーツだけを次に持っていける
- 試作で得た学びを捨てずに済む

だから Loomit は、ローカルファーストの CLI とファイル構造から始めている。

## 目指しているのは、試作をなくすことではない

Loomit は、試作そのものを不要にする魔法の道具ではない。

試作には、実際に着てみないと分からないこと、触ってみないと分からないこと、布で見ないと分からないことがある。

それでも、試作の前にできることはある。

- 明らかに合わない接続を先に見つける
- 今回の服で確認すべきリスクを絞る
- 前回の失敗を次の test 候補に変える
- 「なぜこの変更をしたか」をあとから読めるようにする

Loomit が目指しているのは、試作をなくすことではなく、試作をより意図的で、説明可能で、無駄の少ないものにすることである。
