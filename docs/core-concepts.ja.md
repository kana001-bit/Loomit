# Core Concepts

Loomit は、いくつかのシンプルな概念を組み合わせて服づくりを管理します。
この文書では、それぞれの概念が何を表し、どのような役割を持つのかを説明します。

## Project

**Project** は、一着の服を表します。

Loomit は、一着ごとに独立したプロジェクトを作成します。
プロジェクトには、その服で使用するパーツ、設定、試作メモ、出力設定などが含まれます。

設計案を試したい場合は、既存の Project を `fork` し、元の服とは独立した新しい案として試行錯誤できます。

---

## Part

**Part** は、服を構成する部品です。

身頃、袖、襟、カフスなど、それぞれのパーツは独立して管理されます。

パーツ単位で寸法や条件を持ち、互換性の検証や差分比較、再利用の基本単位になります。

---

## Prototype Notes

**Prototype Notes** は、試作から得られた知見を記録するためのデータです。

「腕が上がりにくい」「ここが突っ張る」「次回はこの動作を確認したい」といった経験を残し、次の試作や設計判断に活用します。

Prototype Notes はパターンそのものではなく、「服を作る中で得られた知識」を表します。

---

## Diff

**Diff** は、設計変更を意味のある形で比較するための仕組みです。

Loomit が比較したいのはファイルの文字列ではなく、「何を変えたか」です。

例えば、

- ダーツ幅を変更した
- ダーツ位置を移動した
- コネクタの条件を変更した

といった設計上の変更を、人が理解しやすい形で表示します。

Diff は、変更を採用するか、元に戻すかを判断するためのレビュー画面として設計されています。

---

## Variant

**Variant** は、同じ Part の異なる設計を識別するための名前です。

Variant はバージョン番号ではありません。

例えば、パフスリーブとビショップスリーブは、どちらかが新しいわけではなく、それぞれ異なるデザインです。

Loomit は「新旧」ではなく「別の選択肢」として Variant を扱います。
